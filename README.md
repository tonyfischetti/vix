# vix

## Introduction

vix is just a place to keep my particular (neo)vim setup and configuration
so I can easily experiment with it and clone it on different systems. It's
also, of course freely available for other use and measures will be taken
to make its installation easy for other people to use and do whatever they
want with.

`<Leader>` is `\`.

## Plugins

Managed by lazy.nvim, pinned in `lazy-lock.json`. Specs live in
`lua/vix/plugins/`, one file per concern.

### Editing

| plugin | what it does |
| ------ | ------------ |
| mini.nvim (mini.align) | align text, with live preview (`ga`) |
| tcomment_vim | comment toggling (`?` in visual, `gcc`, `gc{motion}`) |
| hop.nvim | jump to a pattern (`s`) or word (`S`) |
| comment-box.nvim | boxed / lined comment headers via `:CB` commands (see below) |
| todo-comments.nvim | highlights TODO, FIXME, HACK, etc. plus a custom CODEX keyword |
| nvim-highlight-colors | inline swatches for hex codes and colour names |
| nvim-cmp + LuaSnip | completion (manual trigger) from LSP, omnifunc, buffer, path and snippets; snippets are the snipmate files in `snippets/` |

### LSP and diagnostics

| plugin | what it does |
| ------ | ------------ |
| mason.nvim, mason-lspconfig, nvim-lspconfig | servers: ts_ls, lua_ls, clangd (system clangd on linux-arm64); r_language_server and hls are configured but not auto-installed |
| tiny-inline-diagnostic | shows diagnostics inline, only for the line under the cursor |
| pretty_hover | nicer rendering of LSP hover docs (`K`) |

### Navigation and windows

| plugin | what it does |
| ------ | ------------ |
| telescope.nvim | fuzzy finding; with fzf-native, symbols, and forks of the project and cmdline extensions |
| nvim-tree.lua | file explorer (`<Leader>ee`) |
| bufferline.nvim | buffer tabs along the top (`<Space>,` / `<Space>.`) |
| vim-maximizer | maximise / restore a split (`<Space>z`) |
| winresizer | resize mode (`<Space>e`) |
| no-neck-pain.nvim | centre the buffer with side padding (`:NoNeckPain`) |
| sunglasses.nvim | dims inactive windows |
| neoscroll.nvim | smooth `<C-u>` / `<C-d>` |
| nvim-scrollbar | scrollbar on the right of each window |

### REPL and notes

| plugin | what it does |
| ------ | ------------ |
| vim-slime | send text to a tmux pane (helpers in `lua/vix/lib/`) |
| obsidian.nvim | obsidian vault integration for markdown files (the maintained `obsidian-nvim` fork); link/tag completion comes from its built-in LSP |

### Appearance

| plugin | what it does |
| ------ | ------------ |
| lualine.nvim | statusline |
| nvim-web-devicons | file icons, with overrides in `devicons.lua` |
| snacks.nvim | `vim.ui.input` prompt, `vim.ui.select` picker (code actions etc.), big-file handling, notifications (`Snacks.notifier.show_history()` for past ones) |
| vim-niji | rainbow parentheses for lisp, scheme, racket, clojure (`<Leader>P` to re-apply) |
| colorschemes | `lcars` (in `colors/`, generated by `goodies/colorscheme-make`) is the default; gotham, tokyonight, nightfox, fluoromachine, oceanic-next, palenight, kanagawa and night-owl are installed for `<Leader>cc`, which loads them on demand (they're not on the startup path) |

### Syntax

vim-jsx-typescript, typescript-vim, vim-cpp-modern, vim-ps1, vim-svelte and
html5.vim, plus the hand-maintained files in `syntax/`. There is no
nvim-treesitter; see `lua/vix/plugins/tree-sitter.lua` for why. Neovim's
bundled parsers still handle markdown and lua.

### Misc

vim-startuptime (`:StartupTime`).

### Commands worth knowing

- `:CB<x><y><z> <n>` — comment-box, where `x` is the box alignment (`l`,
  `c`, `r`), `y` is the text alignment (`l`, `c`, `r`, `a`), `z` is `box` or
  `line`, and `n` is a style from `:CBcatalog`.
- `:Obsidian <subcommand>` — everything obsidian (tab-complete it): `new`,
  `quick_switch`, `search`, `backlinks`, `links`, `template`, `rename`,
  `tags`, `toc`, `extract_note`, `toggle_checkbox`, `today`, `yesterday`,
  `tomorrow`, `dailies`, `open` (in the Obsidian app), ...
- `:NoNeckPain` — centre the buffer.
- `:StartupTime` — profile startup.

## Installation

```
mkdir -p ~/.config
git clone https://github.com/tonyfischetti/vix.git ~/.config/nvim
make -C ~/.config/nvim deps      # nvim binary (pinned) + tools + providers
make -C ~/.config/nvim setup     # plugins, pinned to lazy-lock.json
make -C ~/.config/nvim doctor    # verify everything
```

The Makefile is the single source of truth.  Everything is re-runnable:
`deps` skips the nvim download when the pinned version is already
installed (and auto-detects arm64 vs x86_64 on linux), `setup`
converges the plugin set on exactly what `lazy-lock.json` pins, and
`doctor` checks the whole install — including a clean headless startup
of the full config — exiting nonzero if anything is broken.
